### Query workloads

All query files are comma-separated (`src,dst,distance`), 1-indexed node IDs, split 80/10/10 train/val/test. Query dir by dataset group:

- `Surat` — `all_pairs` (every node pair; train, val, and test are all the same full set)
- `W_*` — `real_workload` (raw GPS trip origin/destination pairs, unsplit) and `real_workload_perturb_500k` (perturbed real GPS trip pairs, 80/10/10 split)
- DIMACS (`FLA`, `E`, `W`, `CTR`, `USA`) — `landmark_30M` (landmark-based sampling strategy, 80/10/10 split)

Exact counts per dataset are in [Detailed statistics](#detailed-statistics).

### Precomputed files

- **`<name>.parts.npz`** — hierarchical graph partitioning for the RNE model, generated by [`generate_parts_file_rne.py`](../src/data_preprocess/generate_parts_file_rne.py). Present for all datasets; level count/sizes grow with graph size (e.g. Surat: 5 levels, 16→64→256→933→2,508; USA: 8 levels up to 23.9M — full breakdown in [Detailed statistics](#detailed-statistics)).
- **`landmark_dim<k>.embeddings.npz`** — shortest-path distances from each node to `k` landmark nodes, generated by [`generate_landmark_distances.py`](../src/data_preprocess/generate_landmark_distances.py) via igraph Dijkstra. `k=61` for all datasets.
- **`node2vec_dim64_epochs1_unweighted_<variant>.embeddings.npz`** — 64-dim node embeddings (unweighted graph, p=q=1, 1 epoch). Variant suffix indicates the library used: `_pyg` (PyTorch Geometric, DIMACS datasets), `_pecanpy` (PecanPy, all DIMACS except CTR/USA), `_openne` (OpenNE, `W_*` and `Surat` datasets only).

## Directory structure

```
data/
├── README.md
├── Surat/                          # sample dataset (bundled with this repo)
├── W_Jinan/                        # sample dataset (bundled with this repo)
├── <name>/                         # one directory per dataset
│   ├── raw/                            # raw downloaded files (DIMACS/Figshare), if applicable
│   ├── <name>.edges                    # edge list
│   ├── <name>.nodes                    # node coordinates
│   ├── <name>.parts.npz                # RNE hierarchical partitioning
│   ├── stats.json                      # cached graph statistics
│   ├── landmark_dim<k>.embeddings.npz  # landmark-distance embeddings
│   ├── node2vec_..._<variant>.embeddings.npz    # node2vec embeddings
│   ├── <query_dir>/                    # query workload (e.g. real_workload_perturb_500k)
│   │   ├── <name>.queries.npz              # single file (all queries), OR
│   │   ├── <name>_train.queries.npz        # train split
│   │   └── <name>_test.queries.npz         # test split
│   └── ...                             # additional query dirs, as needed
└── ...
```

## File formats

`.edges`/`.nodes` files are **comma-separated with no header line**. `.queries.npz`/`.parts.npz`/`.embeddings.npz` are compressed NumPy archives.

| File | Contents | Dtype | Notes |
|---|---|---|---|
| `<name>.edges` | `src,dst,weight` | int, int, float | 1-indexed node IDs; weight in meters |
| `<name>.nodes` | `node_id,x,y` | int, float, float | 1-indexed; x/y are projected coordinates in meters (EPSG:5070 for DIMACS sets; local UTM zone for `W_*`/Surat sets) |
| `stats.json` | graph stats | — | node/edge counts, min/max/avg degree, min/max/avg edge weight, approx. diameter (double-sweep BFS) |
| `*.queries.npz` | keys `src`, `dst`, `dist` | int64, int64, float32 | 1-indexed node IDs; distance in meters |
| `*.parts.npz` | key `data`, shape `(n_nodes, n_levels)` | int64 | hierarchical partitioning; each column is a partition assignment at one level |
| `*.embeddings.npz` | key `data`, shape `(n_nodes, 1 + k)` | float64 | col 0 = 1-indexed node ID, cols 1..k = embedding/landmark-distance values. `landmark_*` files also have a `comment` key (string) |

## Getting more data

Only `Surat` and `W_Jinan` are bundled with this repo. To add another dataset:

**DIMACS** (`FLA`, `E`, `W`, `CTR`, `USA`) — add the dataset name to `DIMACS_DATASETS` in [`download_and_preprocess_data.py`](../src/data_preprocess/download_and_preprocess_data.py), then:

```bash
python src/data_preprocess/download_and_preprocess_data.py
```

This downloads the raw `.gr.gz`/`.co.gz` files to `data/<name>/raw/`, preprocesses the graph (largest connected component, node reindexing), and saves `<name>.edges`/`<name>.nodes`.

**Workload datasets** (`W_Shenzhen`, `W_Chengdu`, `W_Beijing`, `W_Shanghai`, `W_NewYork`, `W_Chicago`) — preprocessed versions are available for download [here](https://purdue0-my.sharepoint.com/:f:/g/personal/gchoudha_purdue_edu/IgAmgeBcawEfQ6kplRlMyoA7Abfi3e3yxK6qKM8LRn_-Tlk?e=XRfvjl). Sources:

## Generating precomputed files

Once `<name>.edges`/`<name>.nodes` exist, generate the remaining files as needed. Run from `src/data_preprocess/` (example dataset: `FLA`):

```bash
cd src/data_preprocess

# RNE hierarchical partitioning
python generate_parts_file_rne.py --data_name FLA

# Landmark-distance embeddings (CatBoost/LandmarkNN)
python generate_landmark_distances.py --data_name FLA --num_landmarks 61

# Node2Vec embeddings (PecanPy backend, dim=64, epochs=1)
python generate_node2vec_embeds_pecanpy.py --data_name FLA

# Query workload -- requires ground-truth queries; build the oracle once first:
#   cd non_ml_index/Hierarchical-Cut-Labelling && make compile && make build DATA_NAME=FLA
python generate_query_data.py --data_name FLA \
    --query_strategy landmark_hl --num_landmarks 30 \
    --save_dir landmark_30M
```

To perturb an existing real-workload query set for a `W_*` dataset (e.g. `W_Jinan`) the same way, see [`generate_query_data.sh`](../src/data_preprocess/generate_query_data.sh) for the per-dataset `--perturb_k`/`--k_hop` values used in this repo.

## Custom datasets

You can preprocess your own dataset by following the [directory structure](#directory-structure) above. At minimum, provide `<name>.edges`, `<name>.nodes`, and queries in a query directory (see [`Surat`](Surat/) for a reference example). Node IDs must be 1-indexed and continuous (1 to N for an N-node graph), and the graph must be connected (unreachable nodes break shortest-path queries).
